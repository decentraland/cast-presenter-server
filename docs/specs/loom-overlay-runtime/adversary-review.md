  - **Background pixel arithmetic.** Canvas size is `Math.round(960) & ~1` × `Math.round(741.8) & ~1`, which is 960×742.
    - Canvas (50, 50) maps to PDF (50/1.2121, (741.8 − 50)/1.2121) = (41.3, 570.7). That is outside the `100..300` square.
    - The index `(50*960+50)*4` is that pixel's red byte, and `bg+3` is its alpha.
    - pdfjs fills an opaque white page background when the page has no transparency group. A hand-written fill-only page has none.
    - A fresh `@napi-rs/canvas` buffer is all zeros, so `red > 200 && alpha === 255` cannot pass on an empty render.

Falling back to a fresh unstamped copy also covers a partial write from a `blendPatch` that throws mid-way. The test row is at `phase-3:207`.
  - **Pre-push guidance** (`plan.md:51`): executors do not push; the person shipping runs the v1 checks and asks before bypassing a hook. This matches the user rule, and the hook at `package.json:17` is correctly described.

## Non-blocking findings (below threshold)

### N1 [LOW] The edge-alpha stability test still passes vacuously under the 20 fps throttle

- **Phase:** 2 (step 6, `phase-2:137`, `:143`, `:144`).
- **Defect:**
  - The pump drops a frame when `Date.now() - lastAcceptedAt < 50` (ported from `camera-overlay-compositor/component.ts:68-70`).
  - The mocked reader delivers frames back to back within one test tick. The second identical frame is therefore dropped before `convert`, so `cameraSeq` never increments and the patch is never rebuilt.
  - The two stamped outputs are then byte-identical whether or not `clearRect` exists, so the round-2 fix does not make the test able to fail.
  - The "next frame still reaches the other callbacks" case (`:143`) hits the same throttle, but it fails loudly, so the executor will notice that one.
- **Impact:** the regression guard for the edge that accumulates to opaque is dead. The implementation is still specified correctly (`phase-2:114`).
- **Remediation (inside step 6):**
  - Advance time by at least 50 ms between delivered frames with `jest.spyOn(Date, 'now')`, in every multi-frame case.
  - In the edge-alpha case, first assert that `onCameraFrame` fired twice, which proves the rebuild happened, and only then compare the two outputs.

### N2 [LOW] `pushIdleFrame` places `baseAsI420` in two different spots

- **Phase:** 3 (step 11, `phase-3:135-137`).
- **Defect:**
  - The early-return list calls `baseAsI420` before any `try`, but the next bullet says "`baseAsI420` runs inside the same `try`".
  - If it runs inside the `try` and throws, the catch's "fresh unstamped copy" has no source buffer. `Buffer.from(undefined)` inside the catch would throw out of the guard.
- **Impact:** low. `rgbaToI420` (`src/logic/color-convert.ts:15-70`) is pure arithmetic over `Buffer.allocUnsafe`, and it does not throw on short input. TypeScript scoping will also push the executor toward one reading. It is a decision gap, not a probable crash.
- **Remediation:** say either "call `baseAsI420` before the `try`; only `stamp` is guarded", or "on a throw from `baseAsI420`, warn and return without pushing".

### N3 [LOW] The failure-path cleanup is specified twice, with session-scoped names

- **Phase:** 3 (step 15 at `phase-3:165`; step 20 at `phase-3:182`; the test row at `phase-3:201`).
- **Defect:**
  - Step 15 adds `overlay.stop()` before `publisher.disconnect()`. Step 20 then says to "apply the same two lines" there too, but those lines use `session.publisher` / `session.cameraOverlay`, and the failure path has only the locals `publisher` / `overlay`. A literal executor either duplicates `stop()` or writes a `session` reference that does not compile.
  - The failure-path test row asserts only `overlay.stop`, not the handler clear.
  - Step 20's "replace the compositor block" relies on the `:1088-1093` anchor to tell the `cameraOverlayCompositor` block apart from the video-compositor `cleanup()` block at `component.ts:1077-1080`. That block must stay.
- **Impact:** a redundant but harmless idempotent `stop()`, or a typecheck error the executor fixes. The failure-path handler clear goes untested. There is a small risk of dropping the video-compositor cleanup if the anchor has drifted.
- **Remediation:**
  - In step 15, write the two lines with local names: `publisher.setPresenterCameraTrackHandler(null); await overlay.stop().catch(() => undefined)`.
  - In step 20, name the target as "the `session.cameraOverlayCompositor` block".
  - Extend row `:201` so it asserts `setPresenterCameraTrackHandler(null)` before `overlay.stop`.
